# Dockerized-Web-Stack

## DevOps Demo: nginx + Flask + MySQL в Docker

Мини-проект для тренировки: nginx как reverse proxy принимает весь
внешний трафик, Flask-приложение читает текст из MySQL и отдаёт его
на веб-странице. Наружу торчит только nginx — контейнеры `web` и `db`
недоступны с хоста напрямую.

## Архитектура

```
                 хост-машина
                      │
                 порт 8080
                      │
                      ▼
            ┌───────────────────┐
            │   nginx (image)   │   ← единственный "вход" снаружи
            └─────────┬─────────┘
                       │  внутренняя docker-сеть
                       ▼
            ┌───────────────────┐
            │  web (Dockerfile) │   ← порт 5000 не публикуется на хост
            └─────────┬─────────┘
                       │
                       ▼
            ┌───────────────────┐
            │   db (image)      │   ← порт 3306 не публикуется на хост
            └───────────────────┘
```

Клиент видит только nginx на порту 8080. Порты `web` (5000) и `db` (3306)
объявлены через `expose`, а не `ports` — это значит, что они доступны
другим контейнерам в той же docker-сети по имени сервиса, но не
проброшены на хост и недоступны снаружи вообще.

## Структура проекта

```
devops-demo/
├── app.py                 # Flask-приложение
├── requirements.txt       # Python-зависимости
├── Dockerfile              # Сборка образа приложения (web)
├── docker-compose.yml      # Оркестрация nginx + web + db
├── nginx/
│   └── nginx.conf           # Конфиг reverse proxy
├── .env.example              # Пример переменных окружения
└── .dockerignore
```

## Запуск

1. Скопируйте `.env.example` в `.env` и при желании поменяйте пароли:
   ```bash
   cp .env.example .env
   ```

2. Соберите и запустите контейнеры:
   ```bash
   docker compose up --build
   ```

3. Откройте в браузере:
   ```
   http://localhost:8080
   ```
   (не 5000 — этот порт больше не проброшен на хост)

4. Проверить, что контейнеры живы:
   ```bash
   docker compose ps
   ```

5. Убедиться, что порты действительно скрыты — попытка достучаться
   напрямую до web или db с хоста должна упасть:
   ```bash
   curl http://localhost:5000    # Connection refused
   mysql -h 127.0.0.1 -P 3306    # Connection refused
   ```

6. Остановить всё:
   ```bash
   docker compose down
   ```
   Чтобы ещё и удалить данные MySQL (volume):
   ```bash
   docker compose down -v
   ```

## Как это устроено (для понимания, не только для запуска)

- **nginx** — официальный образ `nginx:1.27-alpine`, конфиг
  подключается volume'ом из `nginx/nginx.conf`. `proxy_pass http://web:5000`
  работает благодаря встроенному DNS docker-compose: имя сервиса `web`
  резолвится в IP контейнера внутри общей сети проекта.
- **web** — собирается локально из `Dockerfile`. `expose: 5000` вместо
  `ports: 5000:5000` — контейнер слушает порт внутри сети, но docker
  не создаёт для него правило проброса на хост.
- **db** — официальный образ `mysql:8.0`, аналогично без `ports`,
  данные лежат в именованном volume `db_data`.
- **depends_on + healthcheck** — `web` стартует только после того, как
  MySQL реально готов принимать подключения, а `nginx` — после старта `web`.
- **retry-логика в app.py** — дополнительная подстраховка на случай,
  если MySQL всё ещё доинициализируется после прохождения healthcheck.
- Пароли и хост БД не зашиты в код — берутся из переменных окружения
  через `.env` файл.

### Важный нюанс про "скрытые" порты

`expose` в compose — это, по сути, просто документация для читающего
файл человека: docker-контейнеры в одной user-defined сети и так видят
друг друга по всем портам, независимо от `expose`. Реальная изоляция
от внешнего мира достигается тем, что для `web` и `db` **нет секции
`ports`** — именно она создаёт правило `iptables`/проброс с хоста
в контейнер. Если бы вы оставили `ports: "5000:5000"` у `web`, nginx
всё равно работал бы, но и напрямую на 5000 порт можно было бы
достучаться с хоста в обход прокси.

## Что можно потренировать дальше

- Добавить `adminer` или `phpmyadmin` сервис для просмотра БД в браузере
  (тоже без публикации портов наружу — доступ только через nginx-location).
- Настроить TLS в nginx (самоподписанный сертификат для тренировки HTTPS).
- Вынести конфиг в `docker-compose.override.yml` для dev/prod окружений.
- Настроить multi-stage build в Dockerfile, чтобы уменьшить размер образа.
- Добавить `.github/workflows` для CI, который собирает образ при пуше.
- Добавить `docker network` явно с именем, вместо дефолтной сети compose.
